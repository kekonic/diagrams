# Fixing a confusing diagram

Fix what the diagram says before changing how it looks. Render again after each meaningful change.

1. Remove boxes and arrows that do not help answer the reader's question.
2. Correct what each box represents, what each arrow means, and which boundaries are real.
3. Split diagrams that mix whole systems, internal parts, deployments, and step-by-step behavior.
4. Reduce unnecessary long-distance arrows. Add groups only when the grouped things truly belong
   together.
5. Choose a reading direction that follows the main path or hierarchy.
6. Start with normal spacing. Tighten it only if labels remain easy to read and click.
7. Choose a theme suited to where the diagram will appear. Add special colors only when they carry
   meaning.

Do not fix crowding by shrinking text, hiding labels, or manually placing every box. Prefer one
clear overview plus a focused detail diagram.

At normal reading size, reconsider a diagram that is much wider or taller than 16:9, uses labels
that read like sentences, or has arrows crossing most of the page. Shorten labels, reorganize the
diagram, split it, or explain why the unusual shape is necessary.

If two layouts could work, use [compare-layouts.md](compare-layouts.md). Keep the boxes and arrows
the same while comparing them so you are judging layout rather than two different diagrams.
